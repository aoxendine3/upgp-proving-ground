UPGP v3.0: Microarchitectural Side-Channel Verification

Benchmark timing indistinguishability in sandboxed execution environments.

What is UPGP? UPGP (Universal Proving Ground Protocol) provides a framework to measure and mitigate microarchitectural timing leaks in sandboxed event loops. In standard VM configurations, variations in execution paths (e.g. branch predictors, JIT optimizations, or cache states) create timing footprints. If unmitigated, these footprints allow concurrent guest processes or shared event loops to extract internal variables. UPGP introduces active, constant-time shields (such as microtask interleaving masking and deterministic key derivation) to neutralize timing leaks.

Why run this test? Traditional security benchmarks evaluate logical access boundaries (such as system call interceptions). UPGP evaluates microarchitectural side-channels. Running this verification suite allows developers to benchmark timing and variance indistinguishability on their specific host configurations, proving that distinct execution paths remain statistically identical across Welch's t-test, F-test, KS-test, and Wasserstein distance.

Usage Examples

UPGP v3.0 is designed as a standalone, platform-agnostic library for node and typescript environments. The following examples demonstrate VM initialization and BFT consensus timing padding.

1. VM Initialization & JIT Pre-Warming

import { UPGPVM } from 'upgp-proving-ground';

const vm = new UPGPVM('dev-master-passphrase');
vm.deriveEnclaveKeys(['Grant', 'Clark', 'Pierce', 'Reid']);
vm.prewarm(); // Executes 200 cycles of interpreter pre-warming passes

2. Constant-Time Consensus Check

// Executes BFT consensus signature loops padded to target exactly 6.0ms
const signatures = await vm.signConsensusPayloadAsync(
    'sensitive_transaction_payload',
    ['Grant', 'Clark'],                  // Approving enclaves
    ['Grant', 'Clark', 'Pierce', 'Reid'] // All enclaves
);

Verification Guidelines & Protocols

01 / Environmental Isolation ▼
Benchmarks must be performed strictly offline. Local timing evaluations are sensitive to outbound network packet latency and DNS round-trip noise. Ensure background host processes do not exceed 5% total CPU load during benchmarks.
02 / Sandbox Usage Boundaries ▼
This verification package is private, proprietary, and designed exclusively for defensive testing in isolated sandboxes. No pull requests or codebase transfers are permitted. Code execution is restricted to read-only audits on the host system and absolute isolation within the sandboxed container.
